### 1-1. 보드 초기화

필요한 메시지(행동)
- 장기판을 초기화 하라

- 선택한 배치대로 기물들을 배치하라

#### 시나리오
1. 장기 게임을 초기화 한다. - JanggiGame
2. 진영별 배치를 선택한다. - Player
3. 진영에 맞는 기물 타입의 기물을 생성한다. - Piece
4. 각 진영별 기물 배치를 초기화한다. - Board

#### 각 메시지(행동)에 따른 책임을 부여한 객체
#### JanggiGame
- [x] 장기 게임을 초기화 한다.
- Board
- Players

#### Players
- [x] 각 플레이어별 
- 진영 side ENUM

#### Player
- [x] 진영별 배치를 선택한다.
- 진영 side ENUM
- Board

#### Board
- [x] 각 진영별 기물 배치를 초기화한다.
- Map<Position, Piece>
- MAX_ROW
- MIN_ROW
- MAX_COLUMN
- MIN_COLUMN

#### Piece
- [x] 기물 타입의 기물을 생성한다.
- 진영 side ENUM
- 기물 종류 type ENUM

#### Position
- row
- column

### 1-2. 기물 이동

협력명: 장기 기물을 이동한다.

![img.png](img.png)

### 이동 규칙

공통 규칙

- 보드판을 벗어날 수 없다.
- 본인 진영의 말만 이동 시킬 수 있다.
- 상대 진영의 말이 있는 칸으로 이동하면 포획할 수 있다.
- 본인 진영의 말이 있는 칸으로 이동할 수 없다.

시나리오

이동 실패 케이스

1. 1,9에 초 진영의 차가 배치되어 있다.
2. 1,9의 초 진영의 차를 1,10 위치로 이동시킨다.
3. 이동에 실패한다.

이동 실패 케이스

1. 초 플레이어의 턴이다.
2. 10,9에 한 진영의 차가 배치되어 있다.
3. 초 플레이어가 10,9의 말을 이동시킨다.
4. 이동에 실패한다.

이동 실패 케이스

1. 초 플레이어의 턴이다.
2. 1,9에 초 진영의 차, 4,9에 초 진영의 졸이 배치되어 있다.
3. 초 플레이어가 1,9의 차를 4,9의 위치로 이동시킨다.
4. 이동에 실패한다.

### 포

기본 조건: 말을 하나 띄어넘어 잡거나 이동할 수 있다.

- 궁궐 안에서는 대각선으로 이동할 수 있다.
- 뛰어넘는 상대 말이 포가 될수 없다.
- 포끼리는 잡을 수 없다.

구체적인 규칙
- Direction은 차 처럼 직선만 있어야 한다.
- 가는 경로에 기물이 1개만 있어야 한고, 해당 기물은 포가 아니여야 한다.
- 도착 경로에 기물은 포가 아니어야 한다.

### 필요한 메시지 (행동)

- 플레이어들이 번갈아가며 각 기물들을 이동하라 JanggiGame
- 한쪽 진영의 말을 이동하라 (시작위치 → 도착위치) Player
- 기물을 이동시켜라 (시작위치 → 도착위치) Board
- 시작 위치의 기물을 도착위치로 움직일 수 있는지 알려줘 Piece

2. 초 진영이 2,5의 궁을 1,4 위치로 이동 시킨다.
3. 이동이 가능하다

포획 성공 케이스

1. 2,5에 초 진영의 궁, 3,5에 한 진영의 졸이 배치되어 있다.
2. 초 진영이 2,5의 궁을 3,5 위치로 이동 시킨다.
3. 3,5에는 초 진영의 궁이 있다.
4. 2,5에는 비어있다.

이동 실패 케이스 (궁궐 내에 경로가 없는 경우)

1. 2,4에 초 진영의 궁가 배치되어 있다.
2. 초 진영이 2,4의 궁을 1,5 위치로 이동 시킨다.
3. 이동할 수 없다.

### 궁

기본 조건: 궁궐 내에서만 이동 가능 하며, 한 칸 씩 만 이동할 수 있다.

- 상대 진영에게 잡히면 해당 진영은 게임을 패배한다.

#### 점수 계산
- 현재 남아 있는 기물에 대한 점수를 구할 수 있어야 한다.


### 미션 중 기록
#### 상태 위치를 결정할 때 고민한 순간 1회
상태 위치에 대한 책임을 Piece에 둘지 Board에 둘지 고민을 했습니다.
기존에는 기물이 위치를 소유하고 자율적으로 본인의 움직임을 판단하고 움직이도록 하려고 했지만,
전체 보드에 대한 정보도 필연적인 정보였습니다. 또한, 기물을 움직임을 판단하려면 전체 보드 현황에 대한 정보가 필요했기에
데이터가 중복되면 싱크가 맞지 않아서 데이터가 회손이 되거나 동기가 안될 가능성이 있기에 기물을 불변으로 만들고 Board가 전체 현황을 관리하도록 하였습니다.
