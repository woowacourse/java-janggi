# java-janggi

장기 미션 저장소

### Ground Rule

1. 프로그래밍을 진행 전 미션과 문서를 뜯어보고, 이번 사이클에서 얻어갈 목표를 정해보자.

* 상태를 객체로 모델링하고 이유를 설명할 수 있다.
    * 상태란?
    * 모델링하는 이유:
    * 장점:
    * 단점:
* 조건문 대신 다형성을 적용할 수 있다.

2. commit 단위에 대한 논의가 이뤄지고, 규칙을 만들어보자.
    * feat: 커밋명
    * 커밋명은 한국어로 하되, AI에게 구체적인 컨텍스트를 주입시켜 만든다.
    * 커밋의 단위는 TDD하면서 테스트 성공하면 그것을 하나의 단위로 (기능 단위)

3. 페어 프로그래밍의 로테이션의 기준을 명확히 하는 것 어떨까?
    * 기능 단위로 하되, 상대가 완벽하게 납득할 때까지 설명하고 키보드를 잡는다.

4. 테스트를 어떤식으로 작성하면 좋을지 통일해보자. → 테스트 작성 가이드 작성해보자.
    * 테스트는 메서드 단위로 하되, 한 가지 역할만 담당한다.
    * `@DisplayName()` 사용하기
    * DisplayName의 이름은 “조건 + 행동 + 기대결과” 구조
    * 테스트 메서드 이름은 영어로 작성하고, 위 구조를 따른다.

5. 어디까지 설계할것인지를 정해보자.
    * 사용자 요구사항설계
    * 기능 요구사항 설계

# 요구사항 정리

### 사용자 요구사항

- 플레이어 1은 초나라, 플레이어 2는 한나라이다.
- 사용자는 장기의 네 가지 상차림에 대해서 선택한다.
    - 상마마상/마상상마/상마상마/마상마상
    - 왼상차림(상마상마) `LEFT_ELEPHANT`
    - 오른상차림(마상마상) `RIGHT_ELEPHANT`
    - 안상차림(마상상마) `INNER_ELEPHANT`
    - 바깥상차림(상마마상) `OUTER_ELEPHANT`
- 사용자는 턴을 넘기거나, 기물을 움직일 수 있다.

### 기능 요구사항

**1.1단계 - 보드 초기화**

- 게임 시작 시 장기판과 전체 기물을 올바른 위치에 초기화한다.

### 입출력 요구사항

- 사용자에게 상차림 목록 출력

```
======================
1. 왼상차림 (상마상마)
2. 오른상차림 (마상마상)
3. 안상차림 (마상상마)
4. 바깥상차림 (상마마상)
======================
```

- 사용자는 제공된 상차림 목록 중 하나를 선택
- (상차림에 맞게 보드 초기화 후) 세팅된 보드 출력

# 고민한 부분
- TDD를 진행하면서 Game의 생성자를 수정해야 할 일이 생겼음. 게임이 종료되었는지 확인을 위해서는 따로 테스트에 테스트 종료를 위한 보드를 주입해줘야 했는데, 기존의 Game 생성자에서는 그러한 로직이 존재하지 않았음.
- 따라서 private 생성자와 this를 통해서 기존의 생성자를 수정하고, 게임 중간에 대한 정보를 통해서 Game객체를 만들 수 있도록 정적 펙토리 메서드를 만들었음.
- 이런식으로 하면 다른 개발자가 따로 of()를 통해서 게임을 생성하려고 할 수도 있지 않을까 하는 생각을 하게 되었음. 이러한 경우는 어떻게 해야하는걸까?

생각을 해봤던 건 Game을 만드는 경로가 두 개인데, 이를 도메인적으로 
- 새 게임 시작과
- 진행 중 상태로부터 게임을 복원

이렇게 두 가지로 생각을 해보았음.
근데 다른 개발자가 처음 보았을 때 "이거 아무렇게나 만들어도 되는건가? 이거 어떻게 써야하지?" 라는 오해를 할 수 있지 않을까?? 하는 생각을 하게 됨.
