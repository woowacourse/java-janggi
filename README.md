# 장기

## 목표

- 사이클2 요구사항까지 단계적으로 확장한다.
- 도메인 규칙과 저장 책임을 분리하는 방향으로 구현한다.

## 기능 요구 사항

### 보드판 초기화 및 입력

- [x] 진영별 포진 선택
    - [x] 한과 초는 각각 마, 상의 차림을 선택한다.
    - [x] 왼상, 오른상, 안상, 바깥상 차림을 번호로 입력받는다.
    - [x] 올바르지 않은 차림 번호는 예외 처리 후 재입력 받는다.
- [x] 장기판 초기화
    - [x] 선택한 차림에 따라 9x10 장기판을 초기화한다.
    - [x] 초기화된 장기판을 화면에 출력한다.

### 게임 진행 및 이동 입력

- [x] 이동할 기물의 시작 좌표 입력
    - [x] 좌표를 쉼표로 구분해 입력받는다.
    - [x] 범위를 벗어나거나 형식이 잘못된 경우 재입력 받는다.
    - [x] 시작 좌표에 기물이 없으면 예외 처리 후 재입력 받는다.
- [x] 도착 좌표 입력
    - [x] 좌표를 쉼표로 구분해 입력받는다.
    - [x] 범위를 벗어나거나 형식이 잘못된 경우 재입력 받는다.
    - [x] 이동이 불가능한 경우 예외 처리 후 재입력 받는다.
- [x] 이동 성공 시 장기판 상태를 갱신한다.

### 기물 이동 규칙

- [x] 궁
    - [x] 상하좌우로 한 칸 이동 가능하다.
- [x] 사
    - [x] 상하좌우로 한 칸 이동 가능하다.
- [x] 차
    - [x] 직선으로 칸 수 제한 없이 이동 가능하다.
    - [x] 경로에 기물이 있으면 이동할 수 없다.
- [x] 포
    - [x] 직선으로 이동 가능하다.
    - [x] 반드시 다른 기물 하나를 넘어야 이동할 수 있다.
    - [x] 포를 넘을 수 없다.
    - [x] 포가 있는 위치로 이동할 수 없다.
- [x] 마
    - [x] 직선 한 칸 후 대각선 한 칸 이동한다.
    - [x] 직선 경로에 기물이 있으면 이동할 수 없다.
- [x] 상
    - [x] 직선 한 칸 후 대각선 두 칸 이동한다.
    - [x] 직선 및 대각선 경로에 기물이 있으면 이동할 수 없다.
- [x] 병/졸
    - [x] 자신의 진영 기준 전진 또는 좌우 한 칸 이동 가능하다.
    - [x] 뒤로 이동할 수 없다.

### 궁성 규칙

- [x] 궁과 사는 자기 궁성 안에서만 이동할 수 있다.
- [x] 궁과 사는 궁성 안 대각선으로 이동할 수 있다.
- [x] 병/졸은 상대 궁성 안에서 대각선 전진이 가능하다.
- [x] 차는 궁성 대각선 선을 따라 이동할 수 있다.
- [x] 포는 궁성 대각선 선을 따라 이동할 수 있다.

### 게임 종료 및 점수 계산

- [x] 왕이 잡히면 게임을 종료한다.
- [x] 남아 있는 기물의 점수를 계산할 수 있다.
    - [x] 차 13점
    - [x] 포 7점
    - [x] 마 5점
    - [x] 상 3점
    - [x] 사 3점
    - [x] 병/졸 2점
    - [x] 장은 점수 계산에서 제외한다.
    - [x] 한 진영은 덤 1.5점을 가진다.
- [x] 게임 종료 후 최종 보드와 점수를 출력한다.

### DB 적용

- [x] 게임 상태 저장을 위한 테이블을 설계한다.
- [x] 새 게임 시작 시 초기 상태를 저장한다.
- [x] 매 수 종료 후 변경된 상태만 반영해 저장한다.
- [x] 애플리케이션 재시작 후 저장된 게임을 이어서 시작할 수 있다.

## 현재 도메인 구성

- `JanggiGame`
    - 게임 진행 상태, 현재 턴, 종료 상태를 관리한다.
- `Board`
    - 현재 기물 배치 상태를 관리하고 실제 이동과 점수 계산을 담당한다.
- `Palace`
    - 궁성 범위와 대각선 선, 대각선 경로 규칙을 담당한다.
- `Piece`
    - 기물별 이동 규칙을 가진다.
- `Position`
    - 좌표 값과 장기판 범위 검증을 담당한다.
- `Team`, `Turn`, `GameStatus`, `Name`
    - 진영, 차례, 게임 상태, 기물 종류를 표현한다.

## 프로그래밍 요구 사항

- 모든 기능을 TDD로 구현해 단위 테스트가 존재해야 한다. 단, UI(System.out, System.in) 로직은 제외
- 함수(또는 메서드)의 길이가 10라인을 넘어가지 않도록 구현한다.
- 배열 대신 컬렉션을 사용한다.
- 모든 원시 값과 문자열을 포장한다.
- 줄여 쓰지 않는다(축약 금지).
- 일급 컬렉션을 쓴다.
- 모든 엔티티를 작게 유지한다.
- 3개 이상의 인스턴스 변수를 가진 클래스를 쓰지 않는다.

### 추가된 요구 사항

- 도메인의 의존성을 최소한으로 구현한다.
- 한 줄에 점을 하나만 찍는다.
- 게터/세터/프로퍼티를 쓰지 않는다.
- 모든 객체지향 생활 체조 원칙을 잘 지키며 구현한다.
- [프로그래밍 체크리스트](https://github.com/woowacourse/woowacourse-docs/blob/master/cleancode/pr_checklist.md)의 원칙을 지키면서
  프로그래밍한다.
