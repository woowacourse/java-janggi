# 사이클 2

## 목표

- 마감기한 준수

## 추가 기능 요구사항

- 사이클1에서 제외했던 궁성 영역의 규칙을 포함하여 기물의 이동을 구현한다.
- 장기는 왕이 잡히는 경우 게임에서 진다.
- 왕이 잡혔을 때 게임을 종료해야 한다.
- 현재 남아 있는 기물에 대한 점수를 구할 수 있어야 한다.
- 점수 계산 규칙은 직접 요구사항을 분석하여 정의한다.
- 애플리케이션을 재시작하더라도 이전에 하던 장기 게임을 다시 시작할 수 있어야 한다.
- DB를 적용할 때 도메인 객체의 변경을 최소화해야 한다.

## 궁성 영역

- [x] 궁성 영역이 존재한다.
    - [x] 궁성 영역은 x가 4-6 범위이고, y는 1-3, 8-10 범위의 3x3 영역이다.
    - [x] 궁성 내부에는 대각선이 존재한다.
        - 대각선은 중앙과 꼭짓점 사이에만 존재한다.
  ```
  (4,3)-(5,3)-(6,3)   (4,10)-(5,10)-(6,10)
  |   \   |   /   |   |    \   |    /   |
  (4,2)-(5,2)-(6,2)   (4,9) -(5,9) -(6,9)
  |   /   |   \   |   |    /   |    \   |
  (4,1)-(5,1)-(6,1)   (4,8) -(5,8) -(6,8)
    ```
    - [x] 위치가 궁성 영역에 포함하는 지 판단한다.
    - [x] 위치가 궁성 대각선 좌표인지 판단한다.
    - [x] 두 위치가 모두 궁성 대각선 좌표인지 판단한다.
- [x] Team을 기준으로 Palace를 생성한다.
- [x] 궁과 사는 다음과 같은 추가 이동 규칙을 가진다.
    - 궁성 영역 내에서만 이동 가능하다.
    - 상하좌우 1칸 이동 가능하다.
    - 궁성 안에서 연결된 대각선으로 1칸 이동 가능하다.
    - 상하좌우로 한 칸 이동 가능하다.
- [x] 포와 차는 궁성 내에서 추가 이동 규칙을 가진다.
    - 궁성 대각선을 따라 여러 칸 이동 가능하다.
- [x] 졸/병은 궁성 내에서 추가 이동 규칙을 가진다.
    - 궁성 대각선을 따라 한 칸 이동 가능하다.
    - 전진 방향 대각선만 이동 가능하다.
- 마와 상은 추가 궁성 규칙이 없다.

## 게임 종료 조건

- [x] 한 진영의 궁이 잡히면 게임이 종료된다.
    - 상대 기물이 왕의 위치로 이동하면 왕이 잡힌 것으로 판단한다.

## 점수 계산

- [x] 한/초 각 진영에 살아있는(남아있는) 기물의 점수를 계산한다.
  ```
  차: 13점
  포: 7점
  마: 5점
  상: 3점
  사: 3점
  졸/병: 2점
  궁: 0점(즉시 패배)
  ```

## 데이터베이스

### 게임 저장

- [x] 새 게임 저장 시 game을 저장한다.
- [x] 매 턴마다 이동 후에 게임 상태를 저장한다.
    - 게임 상태는 턴, 기물 위치가 있다.

### 게임 실행 복원

- [x] 애플리케이션 시작 시 진행 중인 게임이 있는지 확인한다.
- [x] 진행 중인 게임이 있다면 해당 게임을 이어서 진행한다.
- [x] 진행 중인 게임이 없으면 새 게임을 시작한다.

## 게임방

### 게임방 관리

- [x] 게임방을 생성할 수 있다.
    - 게임방 생성 시 고유 번호가 부여된다.
- [x] 게임방 목록을 조회할 수 있다.
    - 진행 중인 게임방 목록을 확인할 수 있다.
- [x] 게임방에 입장할 수 있다.
    - 게임방 번호를 입력해 입장한다.
    - 입장 시 해당 게임을 이어서 진행한다.
- [x] 게임방을 삭제할 수 있다.
    - 게임이 종료되면 게임방이 삭제된다.

### 게임 실행 흐름

- [x] 애플리케이션 시작 시 메뉴를 출력한다.
  ```
  1. 새 게임방 만들기
  2. 게임방 목록 보기
  3. 게임방 입장하기
  4. 종료
  ```
- [x] 새 게임방 만들기를 선택하면 포진 선택하는 기능으로 넘어간다.
    - 게임이 생성되고 게임이 시작된다.
- [x] 게임방 목록 보기를 선택하면 진행 중인 게임방 번호 목록을 출력한다.
- [x] 게임방 입장하기를 선택하면 게임방 번호를 입력 받는다.
    - 해당 게임 방의 게임을 이어서 진행한다.
- [x] 게임 종료 후 메뉴로 돌아간다.

# 사이클 1

## 목표

- 마감기한 준수

## 기능 요구 사항

### 보드판 초기화 및 입력

- [x] 진영별 포진 선택
    - [x] 한과 초는 각각 초기 기물(마, 상)의 차림을 선택한다.
    - [x] 1: 왼상차림, 2: 오른상 차림, 3: 안상 차림, 4: 바깥상 차림 중 번호로 선택한다
  ```
  한과 초의 차림을 선택하세요.(쉼표로 구분)
  1. 왼상 차림 (상마상마)
  2. 오른상 차림 (마상마상)
  3. 안상 차림 (마상상마)
  4. 바깥상 차림 (상마마상)
  1, 3
  ```
    - [x] 이외의 입력이 들어오면 예외 처리 후 재입력 받는다.
- [x] 장기판 초기화
    - [x] 선택한 포진에 따라 9*10 장기판 위에 기물을 초기화한다.
    - [x] 초기화된 장기판을 화면에 출력한다.
  ```
       一 二 三 四 五 六 七 八 九
    十  車 象 馬 士 一 士 馬 象 車
    九  一 一 一 一 將 一 一 一 一
    八  一 包 一 一 一 一 一 包 一
    七  兵 一 兵 一 兵 一 兵 一 兵
    六  一 一 一 一 一 一 一 一 一
    五  一 一 一 一 一 一 一 一 一
    四  兵 一 兵 一 兵 一 兵 一 兵
    三  一 包 一 一 一 一 一 包 一
    二  一 一 一 一 將 一 一 一 一
    一  車 象 馬 士 一 士 象 馬 車
  ```

### 게임 진행 및 이동 입력

- [x] 이동할 기물 시작 위치 입력
    - [x] 이동할 기물 위치(x, y)를 쉼표를 구분하여 입력 받는다.
    - [x] 좌표가 장기판의 범위를 벗어나거나 형식이 잘못된 경우 재입력을 받는다.
    - [x] 시작 좌표에 기물이 없으면 다시 입력 받는다.
  ```
  이동할 기물의 시작 좌표를 입력하세요.
  2, 3
  ```
- [x] 목표 위치 입력
    - [x] 목표 위치(x, y)를 쉼표로 구분하여 입력 받는다.
    - [x] 좌표가 장기판의 범위를 벗어나거나 형식이 잘못된 경우 재입력을 받는다.
    - [x] 이동이 불가능한 경우 입력을 다시 받는다.
  ```
  도착할 기물의 좌표를 입력하세요.
  4, 4
  ```
- [x] 장기판은 특정 좌표에 기물이 존재하는 지 판단한다.

### 기몰 이동 규칙

- [x] 궁
    - [x] 1칸씩 이동 가능하다.
    - [x] 두 궁이 같은 줄에 기물 없이 마주보면 안된다.
- [x] 사
    - [x] 1칸씩 이동 가능하다.
- [x] 차
    - [x] 직선으로 칸 수 제한 없이 이동 가능하다.
    - [x] 경로에 기물이 있으면 통과할 수 없다.
- [x] 포
    - [x] 직선으로 이동 가능하다.
    - [x] 반드시 다른 기물 하나를 넘어서 이동한다.
    - [x] 포를 넘을 수 없다.
    - [x] 포가 있는 위치에 이동할 수 없다.
- [x] 마
    - [x] 직선 1칸 이동 후 대각선 1칸 이동한다.
    - [x] 직선 경로에 기물이 있으면 이동이 불가능하다.
- [x] 상
    - [x] 직선 1칸 이동 후 대각선 2칸 이동한다.
    - [x] 직선 및 대각선 1칸 경로에 기물이 있으면 이동이 불가능하다.
- [x] 졸/병
    - [x] 자신의 진영 기준으로 전진 또는 좌우 1칸 이동 가능하다.
    - [x] 뒤로 갈 수 없다.

### 초기 도메인 추출

- 장기판(Board)
    - 기물을 특정 위치에 이동 시키는 책임을 가진다.
- 위치(Position)
    - x, y 위치가 장기판에 유효한지 확인하는 책임을 가진다.
- 기물(Piece)
    - 특정 위치가 도착할 수 있는지 확인하는 책임을 가진다.
- 플레이어(Player)
- 팀(Team)
- 차례(Turn)

## **프로그래밍 요구 사항**

- 모든 기능을 TDD로 구현해 단위 테스트가 존재해야 한다. 단, UI(System.out, System.in) 로직은 제외
- 함수(또는 메서드)의 길이가 10라인을 넘어가지 않도록 구현한다.
    - 함수(또는 메소드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- 배열 대신 컬렉션을 사용한다.
- 모든 원시 값과 문자열을 포장한다.
- 줄여 쓰지 않는다(축약 금지).
- 일급 컬렉션을 쓴다.
- 모든 엔티티를 작게 유지한다.
- 3개 이상의 인스턴스 변수를 가진 클래스를 쓰지 않는다.

### **추가된 요구 사항**

- 도메인의 의존성을 최소한으로 구현한다.
- 한 줄에 점을 하나만 찍는다.
- 게터/세터/프로퍼티를 쓰지 않는다.
- 모든 객체지향 생활 체조 원칙을 잘 지키며 구현한다.
- [프로그래밍 체크리스트](https://github.com/woowacourse/woowacourse-docs/blob/master/cleancode/pr_checklist.md)의 원칙을 지키면서
  프로그래밍한다.
