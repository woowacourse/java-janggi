# java-janggi

장기 미션 저장소

## 기능 요구 사항

[장기(Janggi)](https://en.wikipedia.org/wiki/Janggi) 규칙을 참고하여 다음을 구현한다.

### 1.1단계 - 보드 초기화

- 게임 시작 시 장기판과 전체 기물을 올바른 위치에 초기화한다.
- 1.1단계에서는 기물의 이동은 구현하지 않는다.

### 1.2단계 - 기물 이동

- 각 기물의 이동 규칙을 구현한다.
- 기물의 이동 규칙은 직접 요구사항을 분석하여 정의한다.
- 궁성(宮城) 영역은 구현하지 않는다. (사이클2에서 다룬다)

### 2.1단계 - 기물의 확장

- 사이클1에서 제외했던 궁성(宮城) 영역의 규칙을 포함하여 기물의 이동을 구현한다.
- 장기는 왕이 잡히는 경우 게임에서 진다. 왕이 잡혔을 때 게임을 종료해야 한다.
- 현재 남아 있는 기물에 대한 점수를 구할 수 있어야 한다.
- 점수 계산 규칙은 직접 요구사항을 분석하여 정의한다.

### 2.2단계 - DB 적용

필수 요구 사항
- 애플리케이션을 재시작하더라도 이전에 하던 장기 게임을 다시 시작할 수 있어야 한다.
- DB를 적용할 때 도메인 객체의 변경을 최소화해야 한다.

선택 요구 사항
| 필수가 아니다. 필수 요구 사항 구현 후 선택적으로 구현한다.
- 장기 게임방을 만들고 장기 게임방에 입장할 수 있는 기능을 추가한다.

## 프로그래밍 요구 사항

- 자바 코드 컨벤션을 지키면서 프로그래밍한다.
  - 기본적으로 Java Style Guide을 원칙으로 한다.
- indent(인덴트, 들여쓰기) depth를 2를 넘지 않도록 구현한다. 1까지만 허용한다.
  - 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
  - 힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
- 3항 연산자를 쓰지 않는다.
- else 예약어를 쓰지 않는다.
  - else 예약어를 쓰지 말라고 하니 switch/case로 구현하는 경우가 있는데 switch/case도 허용하지 않는다.
  - 힌트: if문에서 값을 반환하는 방식으로 구현하면 else 예약어를 사용하지 않아도 된다.
- 모든 기능을 TDD로 구현해 단위 테스트가 존재해야 한다. 단, UI(System.out, System.in) 로직은 제외
  - 핵심 로직을 구현하는 코드와 UI를 담당하는 로직을 구분한다.
  - UI 로직을 InputView, ResultView와 같은 클래스를 추가해 분리한다.
- 함수(또는 메서드)의 길이가 10라인을 넘어가지 않도록 구현한다.
  - 함수(또는 메소드)가 한 가지 일만 하도록 최대한 작게 만들어라.
- 배열 대신 컬렉션을 사용한다.
- 모든 원시 값과 문자열을 포장한다.
- 줄여 쓰지 않는다(축약 금지).
- 일급 컬렉션을 쓴다.
- 모든 엔티티를 작게 유지한다.
- 3개 이상의 인스턴스 변수를 가진 클래스를 쓰지 않는다.

- 도메인의 의존성을 최소한으로 구현한다.
- 한 줄에 점을 하나만 찍는다.
- 게터/세터/프로퍼티를 쓰지 않는다.
- 모든 객체지향 생활 체조 원칙을 잘 지키며 구현한다.
- [프로그래밍 체크리스트](https://github.com/woowacourse/woowacourse-docs/blob/main/cleancode/pr_checklist.md)의 원칙을 지키면서 프로그래밍한다.
- DB를 적용할 때 도메인 객체의 변경을 최소화해야 한다.


## 기능 명세

- 장기판을 구현한다.
    - 장기판의 올바른 위치에 모든 기물들을 위치시킨다.
    - 초기 위치는 csv를 통해 입력받는다.
    - 유저 기준 아래 쪽에 초나라를, 위 쪽에 한나라를 위치시킨다.

- 각 기물의 이동 규칙을 구현한다.
    - `궁`: 상하좌우 1칸 이동 가능
    - `차`: 상하좌우 n칸 이동 가능(다른 기물 또는 벽에 막히기 전까지)
    - `포`: 상하좌우 n칸 이동 가능(단독으로 이동할 수 없기에 이동 경로 중 적/아군 상관없이 하나의 말을 뛰어넘어야만 이동이 가능) / 포끼리는 서로 넘거나 잡을 수 없다.
    - `마`: 날 일(日)자 형태로 이동 가능 (상/하/좌/우 한 칸 이동 → 이동 방향 기준 대각선 위로 한 칸 이동) / 이동 경로 사이에 다른 말이 있을 경우 이동 불가
    - `상`: 쓸 용(用)자 형태로 이동 가능 (상/하/좌/우 한 칸 이동 → 이동 방향 기준 대각선 위로 두 칸 이동) / 이동 경로 사이에 다른 말이 있을 경우 이동 불가
    - `사`: 상하좌우 1칸 이동 가능
    - `쫄`/`병`: 상좌우 1칸 이동 가능 / 뒤로 이동 불가

- 궁성 영역의 규칙을 구현한다.
  - 궁, 사는 궁성 밖을 나갈 수 없다.
  - 궁성의 대각선을 마, 상은 이용할 수 없다.

- 왕이 잡혔을 때 게임을 종료해야 한다.

- 현재 남아 있는 기물에 대한 점수를 구할 수 있어야 한다.
  - `궁`: 0점
  - `차`: 13점
  - `포`: 7점
  - `마`: 5점
  - `상`: 3점
  - `사`: 3점
  - `쫄`/`병`: 2점

- 이전에 하던 장기 게임을 다시 시작할 수 있어야 한다.
  - DB를 연동하여 현재 기물의 위치 정보를 저장한다.

### 입출력 흐름
- **1. 저장된 게임 목록 출력**
  - **1-1.** 저장된 게임이 없다면 새로운 게임 시작
  - **1-2.** 저장된 게임이 있어도 `0`을 입력하면 새로운 게임 시작
  - **1-3.** 게임 ID 유효성 검사
- **2. 게임 진행**
  - **2-1.** 현재 보드 출력
  - **2-2.** 이동할 말의 위치를 입력
  - **2-3.** 목적지 위치를 입력
  - **2-4.** 위치, 이동에 대한 유효성 검사
  - **2-5.** 변경된 보드 출력
  - **2-6.** 게임 저장 여부 입력
  - **2-7.** 저장했다면 게임을 이어할지 종료할지 입력
  - **2-8.** 이어한다면 2-1로 돌아간다.

### 정상 입력
- 게임을 불러올 ID는 양의 정수로 입력한다.
- 위치 입력은 보드 크기 범위 내부로 입력한다.
  - x 좌표는 0~8, y 좌표는 0~9
